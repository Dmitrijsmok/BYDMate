# Яндекс Алиса в BYDMate

## Новая схема

Alice используется как голосовой интерфейс к существующим возможностям BYDMate, а не как прокси к BYDMate Agent.

Основной путь:

```text
Alice STT
  -> Worker intent router
      -> автомобильная команда -> BYDMate ActionDispatcher
      -> окно/люк % -> AliceApertureController
      -> навигация -> НЕ передаётся в BYDMate на DiLink 3
      -> приложение -> dynamic launcher resolver
      -> автомобильный вопрос -> BYDMate Agent
      -> всё остальное -> остаётся у Alice
```

Для локальных команд не запускаются GigaAM, внешний LLM или BYDMate TTS.

## Автомобильные функции

Прямой путь поддерживает:

- климат, температуру, вентилятор и направления обдува;
- подогрев и вентиляцию сидений;
- окна и люк, включая процентные позиции;
- шторку;
- двери/замки;
- задний и передний багажник;
- свет, ДХО и аварийную сигнализацию;
- холодильник на поддерживаемых автомобилях;
- медиа;
- запуск поддерживаемых приложений.

Навигация через Alice на DiLink 3 отключена после полевого теста build 64023: команда не проходила надёжно через Alice bridge и могла создавать ложное ожидание, что маршрут будет открыт. Навигацией управляет только локальный BYDMate Assistant.

Неподдерживаемая локальным parser автомобильная команда не должна автоматически превращаться в универсальный LLM-запрос. `agent.query` предназначен для вопросов об автомобиле, его состоянии, эксплуатации и данных BYDMate.

## Навигация

Навигационные команды и карточки Alice намеренно отключены на DiLink 3.

Worker не публикует навигационные устройства, dialog router не превращает фразы про маршрут/навигатор в BYDMate-команды, а Android bridge отклоняет даже старые закэшированные navigation actions с `alice_navigation_disabled`.

Если в будущем будет найден и подтверждён отдельный штатный Yandex navigation path, его нужно возвращать как отдельную проверенную возможность, а не как generic BYDMate navigator bridge.

## Приложения

`Алиса, открой YouTube` передаёт имя приложения в динамический launcher resolver. Он ищет установленное приложение по известным package names, launcher label и package token. Поэтому поддерживаются альтернативные сборки, например ReVanced/RVX.

## Карточки

Alice больше не должна дублировать автомобильный dashboard BYDMate.

По умолчанию Worker работает в режиме `ALICE_SMART_HOME_CARDS=compact` и публикует только карточку батареи для диагностики интеграции. Старый полный набор можно включить режимом `legacy`.

Улучшенные карточки окон и шторки остаются кандидатами на замену штатных компонентов BYDMate, а не отдельным UI Alice.

## Agent fallback и #222

Для встроенного BYDMate Agent восстановлен вызов `ttsEngine.warmUp()` перед внешним запросом. Это возвращает оптимизацию линии Build 84/85: пока LLM думает, локальный Sherpa TTS заранее загружает модель.

Этот prewarm не нужен для обычного Alice -> BYDMate пути, потому что там Alice уже выполнила STT и локальные действия не требуют BYDMate TTS.

Полевой тест build 64023 также подтвердил, что Alice не умеет надёжно приглушать музыку через наш STREAM_MUSIC hook на DiLink 3. Поэтому Alice ducking сейчас намеренно не эмулируется. Local BYDMate использует отдельный, подтверждённый физический duck lifecycle.

## DiLink 3

На Android 10 / DiLink 3 одно нажатие кнопки микрофона создаёт keycode 304 и 327. При включённой Alice 304 запускает Alice, а 327 блокируется, чтобы не стартовал второй помощник.

YandexAliceLauncher сохраняет warm path: сначала пытается использовать уже живой Yandex Browser/Alice и только затем идёт по cold-start пути.

## Безопасность

Все записи автомобиля проходят через существующие BYDMate safety gates:

- передний багажник - только на стоянке;
- задний багажник - только при известной скорости 0 км/ч;
- люк не открывается при неизвестной скорости или выше допустимого порога;
- окна не открываются при неизвестной скорости или выше допустимого порога;
- разблокировка дверей контролируется существующим speed gate;
- raw FID/CAN команды через Alice bridge не принимаются.

## Reference Worker

`reference/alice-worker/` содержит single-car reference implementation для Cloudflare Worker или VPS.

Основные настройки:

- `BYDMATE_API_KEY`;
- `YANDEX_CLIENT_ID`;
- `ALICE_DIALOG_TOKEN`;
- `ALICE_SMART_HOME_CARDS=compact|legacy|none`.
